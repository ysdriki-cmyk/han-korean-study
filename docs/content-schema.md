# 教材スプレッドシートの整備案

2026-10-27時点の設計。新しい列名・フラグへのアプリ対応は未実装。現行CSVを置き換える前に読み取り処理とIDの互換性を確認する。

## 共通ルール

既存シートを原本として残し、配信用の `한漢`、`単語`、`TOPIK1` の3タブを作る。共通教材と各人の学習履歴を分ける。

- 1行目だけを見出しにし、列名の重複・結合セル・途中の見出しや合計をなくす。
- IDは文字列の固定値。行番号や並べ替えで変わる数式で採番しない。変更・再利用しない。
- `必須`、`有効` はチェックボックス（TRUE / FALSE）。既存の採用カードは最初に `有効=TRUE` にする。
- 必須項目の欠落は確認し、任意項目の空欄はそのままにする。「なし」「-」で埋めない。
- 複数ヒント・採点用の別解はセル内で1項目1行。括弧の意味や韓国語の正しい分かち書きは保つ。
- 自由記述の訳を機械的に分割して別解にしない。採点用の別解は明示的な列で管理する。
- `state`、`remember`、`read`、`read2` 等の個人評価・管理メモは原本に保管する。共通教材の更新で全利用者の評価を上書きしない。

## 한漢

1行は現在の1カード（韓国語の文字・読み）。漢字候補を1文字ずつ別カードに分解せず、現在の650枚との対応を保つ。

| 列名 | 入力条件・移し方 |
| --- | --- |
| `id` | 必須。元B列 `No.` をそのまま使う |
| `韓国語` | 必須。元E列 `Han` |
| `出題ヒント` | 元F列から問題に使える漢字・日本語を抽出。韓国語の答えを入れない。複数ならセル内改行 |
| `漢字候補` | 元I列 `一覧`。ヒントがない行にも漢字候補か解説を用意する |
| `解説` | 解答後に表示する説明。元F列の全文と元J列の補足を情報を失わず保持 |
| `必須` | 必須。移行時の元F列が空でない442枚をTRUEにし、その後は説明の有無と独立して管理 |
| `有効` | 必須。出題・表示する行はTRUE |

解答前に `出題ヒント` の1項目だけ、解答後に残りのヒント・漢字候補・解説を表示する設計。全問題でヒントがない場合のフォールバックも韓国語を隠して提示する。

元F列には複数候補・括弧・韓国語注記がある。自動整形は下書きにし、答えが問題に漏れないか確認する。解説全文は先に保持する。

## 単語

| 列名 | 入力条件・移し方 |
| --- | --- |
| `id` | 必須。元A列 `No`。元H列の古い `No.` と取り違えない |
| `韓国語` | 必須。元E列 `moments いろいろhello talk` の主見出し |
| `日本語` | 元G列 `youtube subtitle`。日本語・英語のどちらか必須 |
| `英語` | 元F列 `English`。日本語があれば空欄でもよい |
| `別解` | 任意。採点で認める韓国語だけをセル内改行。旧I列 `한글` は確認せず採用しない |
| `例文_韓国語` | 任意。元K列。見出し語と分ける |
| `例文_日本語` | 任意。元N列。対応する例文の訳 |
| `解説` | 任意。利用者に見せる補足だけ。個人用の管理メモは含めない |
| `有効` | 必須。出題・表示する行はTRUE |

現在の採用件数は4,559枚。元CSVの5,005行中446行は韓国語・訳の欠落や見出しなどで除外されている。一括削除せず、空行と補完すれば教材になる行を分けて確認する。

同じ韓国語でも語義・用例が異なる可能性があるため、一括で重複削除しない。複数語の見出しを分割する場合は旧IDとの対応・履歴移行を別途決める。

## TOPIK1

| 列名 | 入力条件・移し方 |
| --- | --- |
| `id` | 必須。元A列 `No` を起点に一意性を確認。重複時は固定の枝番を付け元Noも保持 |
| `韓国語` | 必須。元E列。使用参考例の検索対象 |
| `日本語` | 元G列。日本語・英語のどちらか必須 |
| `英語` | 元F列 |
| `例文_韓国語` | 任意。元K列 |
| `例文_日本語` | 任意。元N列 |
| `有効` | 必須。参考例として表示する行はTRUE |

現在の採用件数は825件。韓国語の先頭・途中・末尾の部分一致で全件を表示する。한漢では単語と訳のみ、単語では例文も表示する現仕様を保つ。単語タブとTOPIK1でNoが同じでも同一カードとは推測しない。

## IDと切り替え

既存の内部IDは `kanji:<元No.>` と `vocabulary:<元No>`。新シートには元の値だけを入れ、`kanji:` 等を重ねて入れない。並べ替え・誤字・訳・解説の修正でIDを変えない。別問題への変更、分割・統合は履歴の扱いを個別に決める。

個人評価は将来のDBで `利用者ID × 教材 × カードID × 쓰기/읽기` ごとに保存する。

1. 原本をバックアップし、配信用3タブに機械的に移せる値と固定IDを移す。
2. 未入力・語義の違う重複・複数語の見出し・韓国語を含むヒントを確認する。
3. `有効` と `必須` を入力する。既存の必須442枚を維持する。
4. アプリに新列名、明示的な別解、必須・有効フラグ、TOPIK1の外部取得を実装する。
5. ID・件数差・問題のネタバレ・採点・参考例を確認してから接続先を切り替える。

旧TOPIK1など列位置で読む処理が残るため、アプリ対応前に新しい列順のシートへ接続しない。

公開CSVなら配信用タブだけを公開する。非公開Sheetならサーバーに閲覧権限だけを与え、必要列を配信する。シートが非公開でも、アプリに配信・表示した教材内容は利用者が取得できる。
